# TCPを自作して理解する(Python版)

Pythonで最小限のTCPを1ステップずつ作りながら、TCPの仕組みを体で覚えるための教材です。

## 本との関係

『Rustで始めるTCP自作入門』(小野輝也)の第3章「実装編」と同じ順序で、同じ構成の検証環境(host1 — router — host2、第2章)を使います。各Stepの冒頭に本の対応する節を書いてあるので、本を読みながらPythonで手を動かす、という使い方ができます。本との違いは次の3点です。

- **言語**:Rustではなく Python(TCPの理解に集中するため。Rustへの移植は Step 8 の課題)
- **相手役**:本は自作TCPどうし(host1・host2の両方で ToyTCP)。この教材は host2 で**カーネルのTCP(nc)**を相手にして答え合わせをする
- **設計**:本は受信スレッド+タイマースレッド+条件変数(3.2、3.5.8)。この教材はスレッドなしの単一ループ

## この教材の考え方

- **相手はカーネルの本物のTCP**。自作TCPどうしで通信すると、両方が同じ勘違いをしていても動いてしまいます。ここでは常にLinuxカーネルのTCP(`nc` コマンド)を相手にして、パケットと `ss` コマンドで答え合わせをします。
- **sudo不要**。本は `sudo ip netns exec ...` で操作しますが、この教材は仮想ネットワークをユーザー名前空間で作るので管理者権限はいりません(`lab/lab.sh exec host1 ...` が `sudo ip netns exec host1 ...` に相当)。
- **各ステップは「動かす → 読む → 壊す → 説明する」**。動いたところで満足せず、わざと壊して何が起きるかを見て、最後に自分の言葉で説明できるかを確認します。
- **スレッドを使わない設計**。TCPそのものと関係ない難しさ(ロック、競合)を排除して、状態遷移だけに集中します。

## 最短で動かす

```bash
python3 -m unittest                        # Step 1
lab/lab.sh start                           # 仮想ネットワーク起動

# 端末A
lab/lab.sh exec host2 nc -l -p 9000
# 端末B
lab/lab.sh exec host1 python3 steps/step07_close.py client 9000
```

端末Bに、ハンドシェイク → データ送信 → 4ウェイ切断のログが流れれば環境は正常です。

## 全体像の復習

```
 アプリケーション層   HTTP など               ← 荷物の中身
 トランスポート層     ★TCP(ここを作る)        ← 小分け・番号付け・再送・並べ直し・ポート番号
 インターネット層     IP(カーネルに任せる)     ← 宛先まで運ぶ。届く保証はない
 リンク層            Ethernet(仮想NIC)       ← 隣まで運ぶ
```

IPは「なくなる・順番が入れ替わる・重複する」が普通に起きる土台です。TCPの仕組みのほぼすべては、その上に信頼できるバイトの流れを作るためにあります。
